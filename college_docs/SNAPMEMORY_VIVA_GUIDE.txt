   - "Sir, we used the latest React 19 for fast component rendering and smooth UI.

   - "We used Tailwind for modern dark-mode styling, responsive layouts for mobile 
     and laptop, and clean glassmorphism cards."

5. @vladmandic/face-api (TensorFlow.js):
   - "This is our AI face recognition library. It runs directly inside the client's

     with PostgreSQL and secure cloud storage buckets for high-res images."

8. Vercel:
   - "The live website is hosted on Vercel's global edge network with custom cache-control 
     headers so users always get the freshest version without browser lag."

📌 PART 5: AI FACE RECOGNITION (Examiner Ka Favorite Question)
================================================================================
Examiner 100% puchega: "AI face matching kaise kaam karta hai? Explain simply."

Answer in 4 easy steps (Examiner impress ho jayega):

1. Face Detection:
   "First, when the user uploads a selfie, our model (Tiny Face Detector / SSD MobileNet) 
   finds where the face is located in the image and draws a box around it."

2. 68 Landmark Points:
   "Second, the AI marks 68 key points on the face — like eye corners, eyebrows, 
   nose tip, lips, and jawline. This helps align the face even if the person is 
   tilting their head slightly."

3. 128-Number Descriptor (Embedding):
   "Third, the neural network converts the face into a list of 128 mathematical numbers 
   called a 'Face Descriptor'. These 128 numbers represent the unique structure of that face."

4. Distance Matching (Euclidean Distance):
   "Finally, the app compares the selfie's 128 numbers with the 128 numbers of all 
   photos in the event. We calculate the Euclidean Distance between them.
   If the distance is less than 0.60, it's a MATCH!
   The smaller the distance, the higher the confidence percentage (like 90%+ match)."

⭐ THE BIGGEST VIVA HIGHLIGHT — PRIVACY:
"Sir, the most important feature is PRIVACY. All AI processing happens right inside 
the user's browser (client-side WebGL). The selfie is NOT uploaded to any third-party 
server, and face data is never stored or sold."

📌 PART 7: TOP 20 VIVA QUESTIONS (Direct & Natural Student Answers)
================================================================================

Q1: What is the USP (Unique Selling Point) of SnapMemory?
Ans: "Sir, three main USPs: 1) Zero-app-install QR code access, 2) 100% original lossless 
photo quality, and 3) In-browser AI face search that protects guest privacy."

Q2: Is the AI running on your server or on the user's phone/laptop?
Ans: "It runs completely in the user's browser using WebGL and WebAssembly via face-api.js. 
This means zero server AI compute cost and 100% biometric privacy for guests."

Q3: What models are you using for face matching?
Ans: "We use SSD MobileNet V1 and TinyFaceDetector for finding faces, FaceLandmark68Net 
for 68 facial points, and FaceRecognitionNet for the 128-D embeddings."

Q4: What if two people look similar, like brothers or twins?
Ans: "The neural network analyzes 128 micro-features. We also display a confidence 
percentage so guests can see which photos have a 90%+ match versus borderline matches."

Q5: What happens if lighting is poor or the photo is blurry?
Ans: "We implemented a multi-scale fallback in `faceMatcher.ts`. The detector resizes 
and tries different resolutions (416px, 512px, 320px) and picks the best face bounding box."

Q6: How do guests upload photos if they don't have an account?
Ans: "Each event has a unique encrypted Event ID in the QR code. Guests open the link 
and can drop photos directly into that specific event's upload queue without registration."

Q7: What is the difference between Zustand and Redux?
Ans: "Zustand is modern and very lightweight (around 1KB), with almost no boilerplate code. 
Redux requires complex reducers, dispatchers, and extra setup for the same result."

Q8: Why did you use TypeScript instead of plain JavaScript?
Ans: "TypeScript provides static type checking. In large projects with photos, albums, 
and user objects, it prevents bugs like accessing undefined properties during runtime."

Q9: What database are you using?
Ans: "We designed a PostgreSQL schema hosted on Supabase, with tables for users, events, 
albums, media items, and face descriptors, protected by Row Level Security (RLS)."

Q10: How do you prevent offensive photos from being uploaded?
Ans: "Event hosts can turn on 'Contributor Approval Mode'. In this mode, guest photos 
go into a review queue and only show in the public gallery after the host approves them."

Q11: Can a private event be protected with a password?
Ans: "Yes, hosts can set their event to 'Password-Protected'. Guests must enter a 4-to-6 
digit PIN before the gallery unlocks."

Q12: How does your Download Center work?
Ans: "Guests can select specific photos with checkboxes or click one button to download 
the entire album packed into a ZIP file generated on the fly."

Q13: What happens if an image link fails or external CDN goes down?
Ans: "Every photo image tag has an `onError` fallback handler. If an image link fails, 
it automatically replaces it with a clean local backup photo so there are no broken icons."

Q14: How does your new multi-user authentication work?
Ans: "Users can register with their own name, email, and password with real-time match 
validation and strength feedback. We also built an authentic Google OAuth consent modal."

Q15: What are the WhatsApp-style avatars in your project?
Ans: "Instead of generic grey pictures, the app takes the user's first letter and gives 
it a stylish colored circular background based on the user's name."

Q16: How is this website responsive on mobile phones?
Ans: "We used Tailwind CSS mobile-first responsive breakpoints (`sm:`, `md:`, `lg:`). 
The navigation collapses into a mobile drawer, and photos switch from 4 columns to 2 columns."

Q17: How did you fix stale caching on Vercel?
Ans: "We added `no-cache, no-store, must-revalidate` headers in `vercel.json` for HTML files. 
Whenever we push new code to GitHub, browsers immediately load the latest version."

Q18: What is PWA and why did you choose it over an Android APK?
Ans: "A Progressive Web App runs directly in Chrome/Safari without downloading an APK. 
At a wedding or fest, guests will easily scan a QR code, but they won't install a 50MB app."

Q19: What is EXIF metadata?
Ans: "EXIF data contains camera details, ISO, and original capture time. Chat apps delete 
this data, but SnapMemory keeps it so photos can be arranged in exact chronological order."

Q20: What are your future plans for SnapMemory?
Ans: "We plan to add video face recognition for ceremony clips, automatic duplicate photo 
detection, and a live slideshow mode for projector screens during the event."
