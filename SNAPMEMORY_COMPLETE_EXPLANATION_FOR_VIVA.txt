👉 ENGLISH ANSWER (Examiner / External ke samne confident bolne ke liye):
"Good morning Sir/Ma'am. Our project is SnapMemory — an AI-powered smart event media 
sharing and intelligent facial-recognition retrieval platform. 

In traditional events like weddings, college fests, and conferences, guest photo collection 
is broken: WhatsApp destroys image quality through heavy compression and exposes phone numbers, 
while Google Drive requires manual curation, permissions, and lacks face discovery.

SnapMemory solves this through three core pillars:
1. Zero-Friction QR Onboarding: Guests scan a table QR code and access or upload photos instantly 
   via a Progressive Web App (PWA) with zero mandatory app downloads.
2. Lossless Original Resolution: All photographs retain 100% original sensor resolution, 
   color fidelity, and EXIF camera metadata.
3. On-Device AI Face Recognition: Powered by face-api.js and WebGL. A guest simply takes a 
   selfie, and our client-side neural network computes 128-dimensional facial embeddings to 
   instantly filter every photo containing that guest in under 2 seconds — with 100% biometric 
   privacy, because no face data ever leaves the user's browser."

📌 SECTION 5: AI FACE RECOGNITION DEEP DIVE (Examiner's Most Technical Questions)
================================================================================
Teacher puchega: "How does the AI face matching actually work under the hood?"
Answer in 6 crystal-clear technical steps:

Step 1: Local Model Loading (`public/models/`)
- Humne weights ko `public/models/` me locally store kiya hai:
  • `ssd_mobilenetv1_model` (Accurate face bounding box localization)
  • `face_landmark_68_model` (68 anatomical landmark points)
  • `face_recognition_model` (ResNet-34 based 128-D descriptor extractor)
- Models locally serve hote hain (0ms latency, zero CORS failures, zero external API cost).

Step 2: Face Detection & Scaling
- Selfie image par `detectSingleFace` ya `detectAllFaces` run hota hai.
- Multi-scale pyramid analysis (416px, 512px, 320px, 224px) use hoti hai taaki door khade 
  ya low-light chehre bhi detect ho sakein.
- Agar multiple faces hain, toh area calculation `(width * height)` se primary selfie 
  face isolate hota hai.

Step 3: 68-Point Facial Landmark Alignment
- Chehre ke 68 specific anatomical points extract hote hain:
  • Points 1-17: Jawline contour
  • Points 18-27: Eyebrows
  • Points 28-36: Nose bridge and tip
  • Points 37-48: Eyes (eye corners and pupils)
  • Points 49-68: Outer and inner lip boundaries
- Image ko affine transformation se standardize kiya jata hai (rotate/align straight).

Step 4: 128-Dimensional Embedding Extraction
- Pre-aligned face patch ko deep neural network (ResNet architecture) me pass kiya jata hai.
- Output hota hai ek Float32Array of length 128 (128-D Feature Vector).
- Har number chehre ke unique mathematical features represent karta hai.

Step 5: Euclidean Distance Comparison
- Guest ki selfie ke descriptor (Vector A) aur gallery photo ke descriptor (Vector B) 
  ke beech mathematical Euclidean Distance ($d$) calculate hoti hai:
  
      d(A, B) = sqrt( sum_{i=1}^{128} (A_i - B_i)^2 )

- Rule:
  • Agar $d < 0.60$: Chehra MATCH ho gaya!
  • Match Confidence = max(0, min(100, (1 - d) * 100)) %
  • E.g., distance 0.25 = 75% match, distance 0.12 = 88% match.

Step 6: Biometric Privacy by Design (GDPR Compliant)
- Sabhi matrix operations client-side browser RAM (WebGL) me hote hain.
- Raw selfie server par transmit nahi hoti.
- Search khatam hote hi Float32Array memory se purge ho jati hai.

📌 SECTION 7: TOP 25 VIVA & EXAM QUESTIONS (Direct High-Scoring Answers)
================================================================================

Q1: What is the main problem SnapMemory solves?
Ans: SnapMemory eliminates fragmented and compressed photo sharing in social events. 
It replaces messy WhatsApp groups and permission-heavy Google Drives with zero-friction 
QR code access, lossless full-resolution storage, and instant AI face retrieval.

Q2: Why did you choose React 19 over older versions or vanilla JS?
Ans: React 19 introduces automated memoization, concurrent transitions, actions, 
and improved server/client streaming. It delivers superior rendering performance 
for large virtualized media grids containing hundreds of photos.

Q3: What is the difference between client-side and server-side face recognition?
Ans: Server-side AI requires uploading user selfies to cloud servers, consuming heavy GPU 
compute costs and creating severe privacy liabilities. Client-side AI (our approach) runs 
inside the user's browser via WebAssembly and WebGL. It is 100% private, zero-cost to host, 
and delivers instantaneous feedback.

Q4: What is face-api.js and which models are you using?
Ans: face-api.js is a JavaScript implementation of deep convolutional neural networks 
built on TensorFlow.js. We use TinyFaceDetector / SSD MobileNet V1 for face bounding box 
detection, FaceLandmark68Net for alignment, and FaceRecognitionNet for generating 128-D descriptors.

Q5: What is Euclidean Distance and how is it used here?
Ans: Euclidean distance is the geometric straight-line distance between two points in 
Euclidean space. In our project, it calculates the difference between two 128-dimensional 
vectors. A distance below 0.60 indicates the two faces belong to the same person.

Q6: How do guests upload photos without logging in?
Ans: The event QR code contains a unique, cryptographically secure Event ID. Guests scan the 
code to open the event in their mobile browser, uploading photos directly to that event's 
public contribution endpoint without having to fill out a registration form.

Q7: What is Zustand and why did you choose it over Redux?
Ans: Zustand is a minimalist state-management library. Unlike Redux, it has zero boilerplate, 
does not require wrapping the app in context providers, has no reducer ceremony, and has a 
tiny bundle size (~1.2KB vs Redux's ~10KB+).

Q8: How does your authentication work?
Ans: SnapMemory features a dual-mode Auth system: standard email/password registration with 
real-time match validation, a 4-level strength meter, and an authentic Google OAuth modal. 
Active sessions are maintained securely with token persistence and role-based access.

Q9: What are WhatsApp-style profile avatars in your project?
Ans: Instead of static placeholder images, our system dynamically extracts the user's first 
initial via `getFirstLetter(name)` and computes a deterministic color palette from 8 gradient 
themes using character code hashing.

Q10: What happens if an image fails to load or an external CDN returns 404?
Ans: Every `<img>` tag is wrapped with an `onError` event handler that swaps any broken link 
with a verified, high-definition local fallback, preventing broken image placeholders.

Q11: How do you handle large image uploads without freezing the UI?
Ans: Uploads are processed asynchronously using Web Workers for thumbnail generation and 
virtualized rendering (`@tanstack/react-virtual`), keeping DOM nodes minimal and framerates at 60fps.

Q12: What security measures prevent strangers from accessing private events?
Ans: Hosts can configure events as 'Password-Protected' or 'Unlisted'. Password-protected 
events require a 4-to-6 digit PIN before media decryption or gallery rendering occurs.

Q13: How is GDPR compliance handled regarding facial biometrics?
Ans: We follow 'Privacy by Design'. Facial embeddings are generated in transient client RAM 
and never stored on server disks. Furthermore, our Legal Center features an explicit 'Right to 
Erasure' (Forget Me) workflow where users can delete all uploaded media.

Q14: What is the purpose of the new "Find My Photos Hub" (`/find-my-photos`)?
Ans: It serves as a global discovery portal. Guests who arrive via the website footer or 
direct URL can search any event by code/PIN or launch instant face recognition on demo events.

Q15: What pricing model have you implemented in the project?
Ans: We implemented a 3-tier freemium model: Free Starter (₹0 for intimate parties), Pro 
Celebration (₹499 with AI face recognition), and Studio & Agency (₹999 for full event coverage).

Q16: How do you prevent stale caching issues when deploying new versions to Vercel?
Ans: We configured explicit cache-control headers in `vercel.json` (`no-cache, no-store, 
must-revalidate` for `index.html`), ensuring client browsers immediately fetch the latest bundle.

Q17: What is a Progressive Web App (PWA) and why is it better than a Native App here?
Ans: A PWA runs directly inside mobile web browsers with native-like capabilities (camera 
access, full-screen, offline cache). For one-time events, guests are 10x more likely to scan 
a QR code than install a 50MB app from the Play Store.

Q18: What is the purpose of the Download Center (`/downloads`)?
Ans: It allows attendees and hosts to perform selective multi-photo downloads or download an 
entire event album as a single, compressed ZIP file without manual individual saves.

Q19: What role-based permissions exist in the platform?
Ans: Three tiers: 
1. Host/Owner (Full administrative rights, event settings, deletion).
2. Contributor (Approved uploaders, album creators).
3. Guest/Viewer (Browsing, downloading, selfie matching).

Q20: How do you prevent offensive or trolling photos from appearing in the gallery?
Ans: Hosts can enable 'Contributor Approval Mode'. All guest uploads enter a moderation 
staging queue in the Host Dashboard and only go live after the host clicks 'Approve'.

Q21: What is EXIF data and why is preserving it important?
Ans: EXIF (Exchangeable Image File Format) stores metadata such as camera model, focal length, 
ISO, and capture timestamp. Messaging apps strip this; SnapMemory preserves it so albums can 
be accurately sorted chronologically.

Q22: What are the key performance metrics of the app?
Ans: Build time is 1.19s, bundle gzip size is ~570KB, face landmark extraction takes ~120ms 
on standard mobile chipsets, and gallery masonry maintains 60 FPS scrolling.

Q23: What database indices are created for fast searching?
Ans: B-Tree indices on `events(id)`, `media(event_id)`, `albums(event_id)`, and composite 
indices on `(event_id, created_at)` for instant chronological feed queries.

Q24: What were the major technical challenges faced during development?
Ans: 
1. Running heavy neural models inside mobile browsers without memory leaks (resolved via 
   model quantization and input size downsizing to 320/416px).
2. Cross-browser canvas CORS headers when fetching remote images (resolved via local-first 
   model serving in `public/models/`).
3. Handling multi-scale face detection for distant faces in crowd shots.

Q25: What is the future scope of SnapMemory?
Ans: 
1. Real-time video face detection for ceremony recordings.
2. Automated duplicate & blurry photo culling using perceptual hashing.
3. Live HDMI/Chromecast slideshow stream for wedding projector screens.
