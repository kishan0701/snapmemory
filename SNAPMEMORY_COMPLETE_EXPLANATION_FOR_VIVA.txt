📌 1. EXAMINER AGAR PUCHE: "WHAT IS YOUR PROJECT?" (1-Minute Answer)
--------------------------------------------------------------------------------
👉 English mein kya bolna hai:
"Sir/Ma'am, our project is SnapMemory. It is an AI-powered smart event media 
sharing platform designed for weddings, college fests, and social gatherings. 
It solves the problem of photo collection and discovery using zero-friction QR code 
onboarding and client-side AI face recognition. Instead of scrolling through 
thousands of event photos, a guest simply uploads a selfie, and our in-browser AI 
instantly finds and filters all photos containing that guest."

👉 Hindi mein simple matlab:
Shadi, birthday ya college fest ke baad sab log photos WhatsApp pe bhejte hain jisse 
quality kharab (compress) ho jaati hai, ya Google Drive links me permission ka lafda 
hota hai. SnapMemory mein host ek QR code generate karta hai. Guests bina kisi app 
download ya login ke photos upload kar sakte hain. Aur sabse bada feature yeh hai ki 
guest apni selfie daal kar pure event ke hazaron photos me se sirf apni photos 1 second 
mein dhoondh sakta hai (AI Face Matching se)!

📌 2. PROBLEM VS SOLUTION (Kyun Banaya Yeh Project?)
--------------------------------------------------------------------------------
❌ Purana Tareeka (WhatsApp / Google Drive):
1. WhatsApp: Photo compress ho jaati hai (blur ho jati hai), aur group me sabka 
   phone number sabko dikh jaata hai (privacy leak).
2. Google Drive: Bohot boring hai. Pehle link maango, permission do, aur event ke baad 
   2000 photos me se apni photo dhoondhte dhoondhte thak jaoge.
3. Native Mobile Apps: Koi bhi shadi ya fest me naya app install nahi karna chahta.

✅ SnapMemory Ka Solution:
1. Zero App Install: PWA (Web app) hai, browser me turant khulta hai.
2. Full Quality: Original resolution aur camera details (EXIF) safe rehti hain.
3. AI Face Recognition: Selfie daalo aur apni photos turant paao.
4. Privacy Controls: Host decide karega ki event Public hai, Password-protected hai, 
   ya Invite-only.

📌 6. AI FACE RECOGNITION DEEP DIVE (Examiner Ka Favourite Topic!)
--------------------------------------------------------------------------------
Agar teacher puche: "Face matching kaise hota hai technically?"

Answer Step-by-Step:
1. Library: Hum `@vladmandic/face-api` use kar rahe hain jo Google ke TensorFlow.js 
   par based hai.
2. Face Detection: Model 'SSD MobileNet V1' use karke photo me chehra kahan hai dhoondhta hai.
3. Facial Landmarks: Chehre ke 68 key points (aankh, naak, honth, jawline) extract karta hai.
4. Face Descriptor (Embeddings): Chehre ka ek 128-dimensional floating point array (vector) 
   banta hai.
5. Matching Algorithm: Guest ki selfie ke vector aur event photos ke vector ke beech 
   'Euclidean Distance' calculate hoti hai.
   - Agar distance < 0.6 hai, toh MATCH mil gaya!
6. Most Important Point (PRIVACY): 
   AI pure browser ke andar (Client-side WebGL) chalta hai. Kisi bhi guest ka biometric 
   data server pe store nahi hota. 100% Privacy-Preserving!

📌 7. TOP 10 VIVA QUESTIONS & DIRECT ANSWERS (Ratt Lo Inko!)
--------------------------------------------------------------------------------

Q1: Why not just use Google Drive or WhatsApp?
Ans: WhatsApp severely compresses image quality and exposes phone numbers in groups. 
Google Drive lacks live interaction, has permission headaches, and doesn't offer 
instant AI face-matching for guests.

Q2: Is the AI running on a Python server or in the browser?
Ans: It runs 100% in the client's browser using WebAssembly and WebGL via TensorFlow.js. 
This means zero server AI compute cost and complete biometric privacy for guests.

Q3: What database are you using?
Ans: We are using Supabase, which provides a managed PostgreSQL database with Row-Level 
Security (RLS) policies and cloud object storage buckets for original images.

Q4: What is Zustand? Why not Redux?
Ans: Zustand is a modern, lightweight state management library for React. Unlike Redux, 
it has virtually no boilerplate, doesn't require complex reducers/actions, and has a 
tiny bundle size (~1KB vs Redux 10KB+).

Q5: How does a guest upload without logging in?
Ans: Each event has a unique cryptographic Event ID encoded in the QR code. Guests access 
a public upload endpoint scoped strictly to that specific event with rate limiting.

Q6: What happens if two guests look similar (like twins)?
Ans: The face descriptor uses 128 micro-landmarks. We also provide a confidence threshold 
slider so the guest can tighten the similarity tolerance to 75% or 90% for higher accuracy.

Q7: What is Phase 1 and Phase 2 in your code?
Ans: Phase 1 is the complete frontend architecture, state management with mock fixtures, 
and local AI face recognition. Phase 2 connects the live Supabase PostgreSQL backend 
and S3 storage buckets via environment variables.

Q8: What security features have you implemented?
Ans: Role-Based Access Control (Host, Contributor, Guest), Route guards (ProtectedRoute), 
password protection for private events, and event deletion safety confirmations.

Q9: Is the application mobile responsive?
Ans: Yes, fully responsive across mobile, tablet, and desktop using Tailwind CSS v4 
flexbox/grid layouts and touch-friendly gestures.

Q10: What are your future enhancements?
Ans: Video face recognition, automated duplicate photo detection, and live photo slideshow 
for event projector screens.
