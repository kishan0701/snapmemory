2. INTRODUCTION / BACKGROUND
--------------------------------------------------------------------------------
In personal, academic, and social gatherings (such as college annual festivals, 
weddings, birthdays, seminars, and corporate celebrations), hundreds to thousands 
of high-resolution photographs and videos are captured. However, distributing 
these memories back to the guests remains a chaotic, slow, and frustrating process.

Currently, organizers and attendees rely on two common channels:
1. Instant Messaging (e.g., WhatsApp Groups):
   - Causes heavy lossy compression, degrading DSLR photo quality.
   - Strips away original EXIF metadata (timestamps, camera details).
   - Severe privacy risk: Everyone's private phone number is exposed to hundreds 
     of unfamiliar group members.
2. Cloud Storage Drives (e.g., Google Drive, Dropbox):
   - Cumbersome permission barriers ("Request Access" friction).
   - No interactive community feed or live uploads from multiple guests.
   - Finding your own pictures requires manually scrolling through 1,000+ files.

SnapMemory solves this problem by providing a modern, zero-install web application. 
Guests simply scan a table QR code to open the event gallery, upload in original 
lossless quality, and use an integrated Client-Side AI Face Matcher to locate all 
their photos in under 2 seconds by uploading a single selfie.


3. PROBLEM STATEMENT AND MOTIVATION
--------------------------------------------------------------------------------
Problem Statement:
There is no unified, privacy-first, zero-install web platform that allows event 
organizers to crowd-source high-fidelity event photos while enabling guests to 
instantly retrieve only the pictures they appear in without downloading heavy mobile 
apps or exposing their biometric data to centralized servers.

Motivation:
1. Zero App Download Friction:
   Event attendees do not want to download a 60 MB mobile app from Google Play 
   Store for a 3-hour college event or wedding. SnapMemory works instantly on any 
   mobile browser via a dynamic QR code.
2. Lossless Quality Preservation:
   Event photographers shoot in 4K/RAW/HD. Traditional chat apps compress images 
   by up to 80%. SnapMemory preserves the original resolution and color depth.
3. Edge AI & Biometric Privacy:
   Uploading guests' biometric facial data to cloud servers creates legal and 
   privacy hazards. SnapMemory performs deep learning face embeddings directly in 
   the user's browser (Edge AI). No personal facial scan ever leaves the device.
4. Granular Host Control & Moderation:
   Organizers need to moderate what gets posted at college festivals or family 
   events. SnapMemory gives hosts an approval queue for contributor uploads, 
   download permission toggles, and live event telemetry.
5. Practical Real-World Application:
   This project allows us to apply modern Reactive Frontend Architecture (React 18, 
   TypeScript), Database Management (Supabase PostgreSQL), Cloud Storage, and 
   Browser Computer Vision to solve a universal real-world problem.

5. SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
SnapMemory is built upon a modern Three-Tier Client-Cloud Reactive Architecture:

1. Presentation Tier (Frontend):
   - Framework & Language: React 18 with TypeScript for component-based modularity 
     and strict compile-time type safety.
   - Styling & UI: Tailwind CSS with dark-mode neon purple aesthetic, glassmorphism 
     (backdrop-blur), and Lucide React modern iconography.
   - Routing: React Router DOM (v7) managing protected host paths and public QR routes.
   - Animation & Transitions: Smooth UI micro-interactions using Framer Motion.
   - Edge Computer Vision: HTML5 Canvas API and client-side deep neural network 
     inference for facial landmark detection and Euclidean distance matching.
   - Build System: Vite 8 for fast Hot Module Replacement (HMR) and optimized bundles.

2. Application / Logic Tier (Middleware & Services):
   - Service Layer: Abstracted API service layer (`src/services/api.ts`, 
     `src/services/supabase.ts`, `src/services/storage.ts`).
   - Resilient Dual-Mode Design: Connects to live Supabase cloud backend when API keys 
     are present, with an automatic, zero-crash local mock fallback for offline viva demos.
   - Client-Side Compression & Archiving: JSZip & FileSaver libraries for creating 
     multi-image ZIP packages directly inside the browser.
   - State Management: Custom React hooks (`useEvents`, `useMedia`, `useAuth`, 
     `useLocalStorage`) providing predictable, reactive data flow.

3. Data Tier (Database & Cloud Storage):
   - Relational Database: Supabase PostgreSQL 15 storing:
     * `users`: Host and guest profiles, authentication credentials.
     * `events`: Event titles, slugs, dates, venues, privacy settings.
     * `albums`: Categorized sub-folders (Ceremony, Reception, Cultural, Sports).
     * `media`: Photo/video URLs, thumbnail URLs, EXIF metadata, timestamps.
     * `contributors`: Upload requests and host permission status.
     * `analytics`: Unique view counters, download logs, bandwidth metrics.
   - Blob Storage: Supabase Storage Buckets storing original high-resolution assets 
     and optimized CDN thumbnails.

System Flow:
[Guest Scans QR Code] 
        ↓
[React Browser Client opens Event Page (/e/evt-slug)]
        ↓
[Service Layer validates event access & permissions]
        ↓
[Supabase DB / Local Cache returns categorized media & albums]
        ↓
[Guest clicks "Find My Photos" & takes Selfie]
        ↓
[Browser executes Edge AI Facial Inference locally (128-D vectors)]
        ↓
[Photos matching Euclidean distance threshold displayed instantly with % score]
        ↓
[Guest downloads single photo or generates batch ZIP via JSZip]

User Roles:
1. Event Host / Admin: Creates events, customizes settings, approves/rejects 
   contributors, deletes unwanted photos, views analytics.
2. Approved Contributor: Guests with upload privileges who can add photos/videos 
   to the shared event stream.
3. Guest Attendee: Regular visitors who scan QR to browse, search by selfie, and 
   download photos without registration friction.

Security & Privacy Layer:
- Edge Biometric Privacy: Face recognition is 100% client-side; user selfies are 
  never sent to or stored on any central server.
- Role-Based Access Control (RBAC): Sensitive actions (event editing, contributor 
  approval, photo deletion) are restricted to the verified event host.
- Password Security: Multi-level password entropy scoring with real-time feedback.
- Sanitized input and parameterized database calls to prevent SQL injection & XSS.

          VIVA CHEAT-SHEET: TOP 10 QUESTIONS & DIRECT ANSWERS FOR EXAMINERS
================================================================================

Q1: What is the core problem SnapMemory solves?
A1: "Sir/Madam, after weddings or college events, sharing photos through WhatsApp 
    compresses image quality by 80% and leaks phone numbers in huge groups, while 
    Google Drive makes guests scroll through 1,000+ photos to find themselves. 
    SnapMemory solves this by offering instant QR access, original quality uploads, 
    and client-side AI face recognition to find photos in 2 seconds."

Q2: Why did you use Client-Side (Edge) AI instead of a Python/Flask server?
A2: "Two critical reasons, Sir:
    1. Privacy: User selfies never leave their phone or get stored on our server, 
       avoiding biometric privacy violations.
    2. Scalability & Cost: Performing AI inference in the user's browser offloads 
       computation from the server, meaning our backend can handle thousands of 
       guests simultaneously with zero GPU server costs."

Q3: What technologies are used in the Frontend?
A3: "We used React 18 with TypeScript for component-based architecture and strict 
    type safety, Tailwind CSS for dark-mode glassmorphic styling, Lucide React for 
    icons, and Vite 8 as the build tool for blazing fast performance."

Q4: What backend and database did you choose?
A4: "We used Supabase, which provides a managed PostgreSQL 15 database, secure 
    authentication, and cloud storage buckets for media files. We also built an 
    automatic fallback to local storage so the demo never fails even if internet 
    is lost during the viva."

Q5: How does the AI Face Recognition algorithm work?
A5: "When a guest uploads a selfie, the model detects facial landmarks and generates 
    a 128-dimensional biometric embedding vector. It then computes the Euclidean 
    distance between this vector and the pre-analyzed vectors of event photos. 
    Matches below a specific distance threshold are converted into similarity 
    percentage scores and displayed instantly."

Q6: How do QR codes work in your application?
A6: "Each event has a unique slug and ID. The system generates a vector QR code 
    containing the deep link (`https://snapmemory.vercel.app/e/:slug`). When a guest 
    scans it with their phone camera, the browser immediately opens the event page 
    without needing any app installation."

Q7: How are photos protected from spam or unwanted uploads?
A7: "SnapMemory has a Contributor Request Workflow. The host can set an event to 
    'Contributor Approval Required'. Any photo uploaded by a guest enters a pending 
    queue that only appears in the public gallery after the host approves it."

Q8: How does the Download Center work for large galleries?
A8: "Guests can download single images in full quality, or select multiple photos 
    and click 'Download as ZIP'. We use the JSZip library to bundle the selected 
    images into a compressed `.zip` archive directly in the browser."

Q9: What security measures have you implemented?
A9: "We implemented Role-Based Access Control (RBAC) so only hosts can edit events 
    or delete media, client-side password entropy validation with strength meters, 
    and sanitization of all event inputs to prevent XSS."

Q10: Where is your project hosted?
A10: "The source code is hosted on GitHub, and the frontend is continuously deployed 
     on Vercel's global CDN at https://snapmemory.vercel.app/ with automatic CI/CD 
     builds on every commit."
